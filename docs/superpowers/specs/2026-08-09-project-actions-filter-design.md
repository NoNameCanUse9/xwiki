# 项目操作菜单与状态筛选设计

## 目标

将首页项目卡片上的“归档/恢复”按钮替换为三点操作菜单，并增加按项目状态筛选的能力。

## 已确认行为

- 活跃项目菜单：`重命名`、`删除`、`归档`。
- 已归档项目菜单：`重命名`、`删除`、`恢复`。
- 删除操作必须二次确认；确认后删除项目元数据和仓库，并刷新首页列表。
- 重命名使用 Dialog 输入项目名，沿用后端项目名规则；成功后刷新列表并提示结果。
- 首页增加状态筛选：`全部`、`活跃`、`已归档`。
- 筛选没有结果时显示“暂无符合条件的项目”；真正没有任何项目时保留现有空状态。

## 技术方案

- 使用现有 `@base-ui/react/menu` 实现可键盘操作、可点击外部关闭的三点菜单。
- 使用现有 Dialog/Input/Label 组件实现重命名表单。
- 前端 API 层补充：
  - `renameProject(id, name)`：`PATCH /api/v1/projects/:id`。
  - `deleteProject(id)`：`DELETE /api/v1/projects/:id`。
- 归档、恢复继续使用现有 API。
- 筛选状态只存在首页本地，不改变后端列表接口；筛选结果由当前项目列表派生。

## 影响范围

- `web/src/lib/api/projects.ts` 及其测试：新增重命名、删除请求。
- `web/src/routes/home.tsx`：项目菜单、重命名 Dialog、删除确认、状态筛选和空结果状态。
- `web/src/routes/home.test.tsx`：菜单打开、操作调用、筛选和重命名交互回归测试。

## 非目标

- 不新增后端接口；后端 PATCH/DELETE 项目接口已存在。
- 不改变项目卡片的整体视觉风格和导航路径。
- 不实现批量操作。
